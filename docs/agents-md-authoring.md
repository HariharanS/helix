# AGENTS.md Authoring Standard

Helix uses `AGENTS.md` as the default persistent instruction surface. Do not install `.github/copilot-instructions.md`, and do not generate `.github/instructions/*.instructions.md` summaries as part of normal setup.

## Layering Model

| Location | Purpose | Keep Here |
|---|---|---|
| Meta-repo root `AGENTS.md` | Navigation and source-of-truth map | Active workspace lookup, global retrieval rules, directory map |
| `workspaces/AGENTS.md` | Workspace artifact model | What belongs in workspace folders and read order for feature artifacts |
| `workspaces/{id}/AGENTS.md` | Platform context | Repo roles, cross-repo data flow, shared glossary, read order |
| Repo root `AGENTS.md` | Repo baseline | Purpose, domain boundary, architecture, verification, key conventions |
| Nested `AGENTS.md` | Subtree rules | Source, tests, IaC, generated code, or subsystem rules that differ from repo root |

## Size Rules

- Keep each file scannable in one pass.
- Prefer bullets, short tables, and annotated trees over prose.
- Put only durable, non-obvious instructions in `AGENTS.md`.
- Link to README, docs, context bundles, or annex files for details.
- Do not duplicate parent guidance in nested files.
- If a section grows into narrative, move it to `README.md` or `docs/` and link it.

## Required Shape

Each `AGENTS.md` should answer only the questions for its level:

- Where should the agent start reading?
- What is the source of truth for this scope?
- What conventions would an agent otherwise miss?
- What files or directories should the agent avoid or treat specially?
- What verification should the agent prefer when changing this scope?

## Nested File Rules

Create nested `AGENTS.md` only when there is a real convention boundary:

- `src/AGENTS.md` for source layout, domain model, persistence, handlers, and abstractions.
- `tests/AGENTS.md` for test framework, fixture, naming, integration, sandbox, or UI test conventions.
- `infra/AGENTS.md`, `cdk/AGENTS.md`, or equivalent for deployment and IaC conventions.
- generated-code folders when agents must not edit generated files directly.

Do not create nested files just to restate the repo root. A missing nested file means the parent rules apply.

## Forbidden Defaults

- Do not use `.github/copilot-instructions.md` as a Helix-managed file.
- Do not generate `.github/instructions/*.instructions.md` summaries from repo `AGENTS.md`.
- Do not paste a whole README, PRD, tech design, or context bundle into `AGENTS.md`.
- Do not store feature-specific requirements in repo-level `AGENTS.md`.

## Migration Notes

`setup-workspace.ps1` removes only Helix-generated legacy `.instructions.md` summaries that contain the marker:

```html
<!-- Generated by helix/scripts/setup-workspace.ps1 -->
```

User-authored `.instructions.md` files are left in place but are not part of the default Helix instruction surface.
